## Preserved contracts and inspected scope

- Recall: `workbookRecallIsCurrent` checks connected input, session/item, sequence, value and completion; focus transfer requires active-input ownership. Composition handlers and Jamo/completed-syllable logic remain unchanged. Physical iPhone IME remains a separate validation boundary.
- Enter/multi-slot: `workbookEnterAction` cycles to the next empty slot, submits completed responses, then next/retry; deterministic grading updates the mounted outcome and queues persistence. Duplicate order text uses separate expected positions and consumed chip IDs; retry clears batch state. No interaction refactor.
- Unique cycles: `clearWorkbookCycleItem` Set and SQL primary key deduplicate within cycle; SQL locks the progress row `FOR UPDATE`; cycle rollover and chronological migration replay retain immutable attempts. New clientAttemptId across a genuinely new cycle is valid. DB retry uniqueness is `(student_id, client_attempt_id)`.
- Progress floor: prevents a lower scalar server count from rolling back local display for an unchanged catalog. It is not a general proof of cross-device/revision reconciliation; limitations are recorded above.
- Studio: `syncAnnotations` preserves unchanged sentence snapshots; changed/split/new scopes become dirty, retired identities stay recorded. `applyCandidates` preserves confirmed and publisher-backed targets. `studioAuthor` sends only dirty sentences in chunks of 8. `ready_save_studio_state` locks and checks both canonical revision and authoring version.
- Factory/PURE: `generatePassageDeterministicCatalog` reuses unchanged item provenance/keys, validates semantic output, and preserves AUTHORED stages; the surrounding save path records regeneration/review state. `compileStudio` validates confirmed spans. Single-step publish intentionally preserves other published stages; visibility of stale published material remains part of the revision decision above.
- Import: draft boundary confirmation, same-document merge provenance, canonical alignment, uncertain-source DROP/fail-closed checks and dormant Question tests preserved. No source-derived content was regenerated.
- Bootstrap: assigned-scope links and server `has_workbook` determine visibility; word/sentence/bookmark counts load in parallel; last-resume query is bounded. Workbook assistance/answers are bundled once; deterministic inputs/chips/retry/next/stages do not wait for a server.
- Review: per-kind lazy loading and cached tab switches already avoid global busy overlay. Reader cache includes passage revision. Request-local catalog reuse avoids a new global stale cache.

## Validation and final disposition

- Fixed: in-flight durability and acknowledgement handling, single-flight dispatch, session isolation and early restore, stage matching/semantic identity/resume, Review invalidation ownership (including word removal/meaning edits), and idle prefetch ownership.
- Performance: request-local Review catalog reuse. Real API/SQL fixture: **3 bookmarks, 3 catalog reads before → 1 after**; order unchanged; next request sees a changed catalog. This is a query-count improvement, not a measured production latency claim.
- Added `tests/verify-ready-stability.mjs`: **10 executable scenarios**, including success/failure and owner/revision variants. Running the same test against base `2d1235c` produced **9 failures / 1 preserved batch-limit pass**; the final implementation passes all 10. Actual Student function bodies run with controlled deferred transport/storage, rather than regex-only expectations.
- Extended `tests/verify-ready-studio-api.mjs`: real API + PGlite with all migrations, same-ID retry returns one attempt ID and increments progress once, stage identity/resume, request-local catalog query count, ordering and fresh next-request state. The adapter now preserves PostgreSQL error codes so the 23505 path actually executes.
- Final checks: `npm run test:all` (active + dormant Question), `npm run build`, `npm run native:verify`, `git diff --check` all passed. Existing suites cover Workbook, progress, importer/factory, Studio and bootstrap/cache contracts.
- Deleted dead code: **none**. No deletion was proven safe enough to justify review/visual risk. No architecture/state-management replacement, CSS rewrite, migration, merge, or deployment is part of this PR.
- Limits: no production DB inventory, live latency trace, quota-exhausted localStorage test, concurrent browser-tab queue coordination, physical iPhone IME or visual device test was performed. Queue durability assumes successful localStorage writes; session-token renewal recovery is explicitly unresolved. This fixes future stage mapping; it does not retroactively repair progress floors already contaminated by the old bug.

**Disposition:** Keep the current architecture, but do not call the entire system fully stable yet. Before the next feature expansion, resolve catalog/attempt revision semantics and cycle membership, canonical editor lost-update protection, and idempotent server side effects. These require bounded contract changes, not an architecture rewrite.
